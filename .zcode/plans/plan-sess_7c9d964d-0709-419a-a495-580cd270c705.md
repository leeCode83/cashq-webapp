### Seams yang dites (konfirmasi via approval plan ini)
TDD loop di **3 seam murni**: `maxAdvance`, `evaluateAdvance`, `verifyProof` (+ `decideFromProof` sebagai komposisi). `launchVerification` **tidak di-unit-test** — seam-nya ekstensi browser (manual test saat integrasi frontend), sesuai skill TDD "test only at pre-agreed seams".

### Loop TDD (vertical slices, red → green)
1. **Setup runner**: install vitest, script, config. (bukan slice merah, prasyarat)
2. Slice 1 `maxAdvance`: test worked-example independen — floor 8.400.000 default → **6.048.000** (= 90% × (8,4 jt − 20%), angka prototipe); pct 0,7 → 4.704.000. Merah → implement → hijau.
3. Slice 2 `evaluateAdvance`: boundary — R = max → lolos (inklusif); R = max+1 → tolak + reason. Merah → implement → hijau.
4. Slice 3 `verifyProof`: fixture ECDSA di-generate sekali dengan key buangan lalu **di-paste sebagai literal** (sumber kebenaran independen); uji perilaku via **tamper cases**: tanda tangan validator diubah 1 byte → gagal; uHash diubah → gagal; allocatorAddress salah → gagal; schemaId tak dikenal → gagal; recipient tidak cocok → gagal; happy path → ok + floor benar. Merah → implement → hijau.
5. Slice 4 `decideFromProof`: proof invalid → 'bukti-tidak-valid' (tanpa throw); proof valid + R dalam batas → approved. Merah → implement → hijau.
6. Slice 5 `launchVerification`: implement tipis tanpa test (seam ekstensi), JSDoc catat cara manual-verify.

### Anti-tautologi
Expected value dari worked example manual (6.048.000 dihitung tangan), fixture literal, dan tamper cases — bukan recomputasi pakai fungsi yang sama.
